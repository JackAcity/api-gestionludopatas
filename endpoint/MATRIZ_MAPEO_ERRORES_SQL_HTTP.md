## 1. Criterios de clasificación

- `400`: JSON ilegible, cuerpo no deserializable o tipo JSON incompatible.
- `401/403`: autenticación o autorización.
- `409`: conflicto con estado persistido, integridad o idempotencia.
- `422`: validación semántica; se usa primero el código funcional específico de la operación cuando exista.
- `500`: fallo interno no clasificado o serialización de respuesta.
- `503`: dependencia SQL no disponible, permisos/configuración incompatibles o deadlock.
- `504`: timeout de persistencia.

## 2. Precedencia normativa de validación API ↔ SQL

| Orden | Condición detectada | HTTP | Código aplicable | Regla |
|---:|---|---:|---|---|
| 1 | JSON ilegible, cuerpo no deserializable o tipo JSON incompatible | 400 | `GL-API-REQ-001` | No se intenta traducir a una validación SQL porque no existe un valor tipado utilizable. |
| 2 | Regla específica de la operación que replica un `THROW` 510xx/511xx | 422 | `GL-CORTE-*` o `GL-PEND-*` específico | Se devuelve el mismo código aunque la API detecte la condición antes de ejecutar el SP. |
| 3 | Regla de contrato sin código funcional específico | 422 | `GL-API-REQ-002` | Es el fallback semántico; no sustituye códigos específicos. |
| 4 | El SP devuelve un error controlado | Según matriz | Mismo código funcional específico | La clasificación debe coincidir con la prevalidación API de la misma condición. |

La propiedad `source` puede ser `api` cuando la prevalidación detecta la regla o `sql` cuando la devuelve el SP; `status`, `code`, `detail` funcional y `retryable` deben permanecer equivalentes.

## 6. Reglas de implementación propuestas

1. Aplicar estrictamente la precedencia de la sección 2 antes de usar `GL-API-REQ-002`.
2. El adaptador SQL debe capturar `SqlException.Number` y aplicar el mapeo más específico antes del fallback `GL-API-UNEXPECTED-001`.
3. Los errores 500xx de despliegue deben detectarse mediante despliegue/startup/healthcheck, bloquear el servicio y no presentarse como errores runtime de un endpoint.
4. Los códigos 510xx/511xx pueden incluir `sqlErrorNumber` porque son controlados y forman parte del contrato SQL.
5. Los errores de conectividad pueden agruparse sin exponer host, instancia, base, puerto ni cadena de conexión.
6. `retryable=true` no obliga a reintentar; UiPath debe aplicar límite, backoff, jitter y contexto de idempotencia.
7. Para crear corte, todo reintento técnico debe reutilizar la misma `Idempotency-Key`.
8. Los conflictos 2601/2627/547 deben registrarse internamente con detalle, pero responder con mensajes públicos sanitizados.
